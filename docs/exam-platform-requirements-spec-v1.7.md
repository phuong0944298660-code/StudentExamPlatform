# 接力教育智慧云平台（题库与考试系统）需求设计说明书

**版本：v1.8**
**更新日期：2026-04-01**
**变更内容：**
- 新增码池管理的用户名搜索功能
- 新增账号列表的激活码关联显示功能

---

## 1. 项目背景与目标

为支持"广西北部湾人工智能大赛（湾赛）"及日常基础教育需求，接力教育拟建设一套集"赛前训练、赛中统考、赛后审分、日常教学"于一体的智慧云平台题库及考试系统。系统需具备高并发承载能力、严格的考试防作弊机制、灵活的题库组卷功能、多角色权限隔离机制以及完善的主观题协同评卷与复核体系。

## 2. 系统角色与核心职责

系统主要划分为以下五类核心角色（包含账号体系隔离）：

1. **管理员（平台运营/赛事方）**：负责全局配置、题库搭建、账号生成、场次与时间轴管理、考务监控、评卷规则配置及成绩审分复核。
2. **学生（训练账号）**：通过激活码获取权限，进行赛前模拟练习、日常刷题，支持答案解析查看与错题回顾。
3. **学生（考试账号）**：以身份证号为唯一标识，免激活码，仅在指定场次和时间内登录，处于严格的防作弊考试环境中。
4. **指导老师**：负责日常教学，拥有资源访问、智能组卷权限、查看所带学生学情。
5. **评卷老师**：负责赛事主观题线上打分、处理复查申请、填写评语。

### 2.1 角色权限说明

- **指导老师**与**评卷老师**为两个独立的角色类型
- 同一个教师账号**可以同时拥有**指导老师和评卷老师两种角色权限
- 教师激活码仅用于解锁对应学段题库和资源中心，与角色权限分配无关
- 角色权限由管理员在账号管理时单独配置

### 2.2 角色权限矩阵

| 功能模块 | 仅指导老师 | 仅评卷老师 | 双重角色（指导+评卷） |
|----------|-----------|-----------|---------------------|
| **练习卷组卷** | ✅ | ❌ | ✅ |
| **查看学情** | ✅（仅所带学生） | ❌ | ✅（仅所带学生） |
| **资源中心浏览** | ✅ | ❌ | ✅ |
| **主观题评卷** | ❌ | ✅ | ✅ |
| **复查申请处理** | ❌ | ✅ | ✅ |
| **评分表上传** | ❌ | ✅ | ✅ |
| **考试场次监控** | ❌ | ❌ | ❌ |
| **成绩发布** | ❌ | ❌ | ❌ |

## 3. 详细功能模块设计

### 3.1 管理员端 (Admin)

管理员端是平台的核心调度中心，涵盖赛务、教务与数据管理。

#### 3.1.1 基础数据与账号管理

* **名单批量导入**：支持下载标准 Excel 模板，批量导入参赛学生/指导老师基础信息。自动建立基础数据库。
* **账号批量生成**：支持训练账号（批量生成密码表）与考试账号（身份证+统一密码，关联学段）的自动化创建与激活管理。账号列表支持查看每个用户关联的激活码信息，便于管理员追踪激活码的使用情况及用户的激活历史。
* **激活码管理**：生成四类激活码（小学教师、小学学生训练、初中教师、初中学生训练），支持快捷配置周期（3个月/半年/1年）或自定义起止日期。支持失效后逐个或批量重新激活，默认周期与上次一致。码池管理支持按"使用者名称"搜索已绑定激活码的用户，便于快速定位激活码的使用情况。
* **设备登录限制**：单点登录（SSO）管控，多端登录强制踢出旧设备。
* **教师-学生关联管理**：
  * **手工关联**：在名单补全页面，逐条为训练账号指定指导老师
  * **批量关联**：通过Excel模板批量导入教师-学生关联关系，覆盖原有关联
  * **关联列表查看**：按指导老师查看其所关联的全部学生训练账号
  * **关联关系修改**：支持解除或更换学生的指导老师关联

#### 3.1.2 题库与资源中心管理

* **题库搭建**：按学段、知识点、题型录入试题及详细解析。
* **计分规则配置**：客观题支持自定义分值，多选题严格执行"少选全对得 1 分，多选/错选不得分"。
* **资源管理与版权保护**：四级目录分类管理，支持各类附件上传。所有资源仅限在线预览，防下载、防复制。

#### 3.1.3 考试场次与时间轴管控（核心控制）

* **场次与门禁控制**：精准匹配"学段-场次-白名单"，未到时间或跨场次严格阻断。只有与场次同学段的考试账号才能被分配。
* **考务时间配置**：
  * 支持配置起始时间与时间长度，根据时间长度自动计算结束时间。
  * 时间长度支持快捷配置：半小时、1小时、1.5小时、1小时45分钟、2小时等，也支持自定义输入。
  * 结束时间支持手动微调（自定义结束时间）。
  * 支持考前修改起止时间，考后延期阅卷截止时间。
* **全局与单人延时**：后台一键开启全场延时，或针对个别故障学生进行单人补时。
* **考场监控大盘**：可视化展示当前在线人数、交卷人数、异常掉线人数。

#### 3.1.4 组卷管理

* **考试卷管理**：管理员配置考试卷，必须指定学段（小学/初中），用于正式考试场次。1个考试卷只能绑定1个场次（不允许多场次共用）。
* **主观题作答方式配置**：按卷配置二选一：
  * 模式A：上传附件（图片/文档/压缩包）
  * 模式B：在线富文本填写
* **历年真题卷**：由管理员将考试卷转换而来，继承原考试卷的学段（无需额外配置），对同学段所有训练账号可见。

#### 3.1.5 赛后审分、评卷进度与数据管理

* **主观题评卷规则配置**：固定取平均分，支持自定义某场次/某题型由几名评卷老师参与打分。
* **评卷任务分配**：考试全部结束后，系统自动按"随机+工作量均衡"分配评卷老师，确保每位老师工作量相当。支持管理员人工调整或转移任务。
* **评卷进度监控**：后台实时查看各场次的主观题评卷进度，精准定位未完成打分的评卷老师。
* **公布成绩时间配置**：在评卷老师完成全部考生的主观题评分后，管理员设置公布时间（精确到 hh:mm），到期自动公布，无需手动开关。
* **复查申请审批与流转**：接收学生端提交的考后成绩复查申请（公布后48小时内），支持批量通过并自动流转。复查老师分配遵循回避原则（排除原评卷老师后随机分配）。
* **多维成绩导出**：按学段/场次筛选导出"完整版"与"脱敏简化版" Excel 成绩表。

### 3.2 指导老师端 (Teacher)

服务于日常教学，侧重于所带学生的学情跟踪与个性化练习卷组卷。

#### 3.2.1 首页工作看板

* **学情分析看板**：展示所带参赛学生（训练账号）的训练活跃度排名、模拟考平均分趋势、个体学生表现追踪（仅查看所带且同学段的学生数据）。
* **快捷组卷入口**：提供快速进入组卷管理的入口。

#### 3.2.2 组卷管理

* **练习卷组卷**：指导老师配置练习卷，必须指定学段（小学/初中）。老师只能配置与自己同学段的卷子。
* **练习卷可见范围**：发布后仅对**自己所带的训练账号**可见（同学段其他学生不可见）。
* **无需审核**：指导老师组的练习卷直接发布给学生，无需管理员审核。

#### 3.2.3 资源与通知

* **资源管理**：浏览资源中心（四级目录），在线预览资源。
* **通知中心**：接收平台通知及所带学生动态。

---

### 3.3 学生端 - 训练账号 (Student Practice)

侧重于知识掌握与赛前热身。

#### 3.3.1 首页数据看板

* **学情总览**：直观展示个人的累计刷题量、练习总时长、平均正确率趋势图。
* **快捷入口**：提供"继续上次练习"、"进入错题本"、"最新练习卷"的快捷点击通道。

#### 3.3.2 模拟训练与错题本

* **练习中心**：
  * **可见范围（学段过滤）**：仅显示同学段的练习卷。
  * **试卷来源**：
    * 自己指导老师组的练习卷（仅自己所带老师组的卷）
    * 历年真题卷（同学段所有训练账号可见）
    * 考试卷转练习卷（同学段所有训练账号可见，如管理员开放）
  * **练习模式**：支持单题练习（快速刷题）与本卷训练（完整模拟）。
  * **即时反馈**：提交后即时展示得分与图文解析。
* **错题本**：答错的客观题自动进入专属错题本，支持按知识点分类回顾。

#### 3.3.3 资源学习

* **资源中心**：浏览四级目录资源。
* **在线预览**：支持课件（PPT/docx）、视频解析等资源在线预览（防下载/防复制）。
* **收藏管理**：支持收藏重要资源。

---

### 3.4 学生端 - 考试账号 (Student Exam)

侧重于公平、稳定、防作弊的沉浸式竞技体验。考试账号不关联指导老师。

#### 3.4.1 极简登录与身份核验

* **身份证+密码登录**：登录后自动跳转对应考场。
* **首次登录强制核对**：核对个人信息（姓名/学校），不显示指导老师（考试账号不关联指导老师）。
* **学段匹配**：系统匹配学段一致的场次，若不匹配则禁止进入。

#### 3.4.2 稳定答题与进度导航

* **答题矩阵导航**：答题界面左侧按题型分布展示每道题的题号矩阵，实时区分"未答"和"已答"状态。支持学生自由点击题号，快速切换至任何题目。
* **进度可视**：页面显著位置实时展示总体答题进度（如：已答 45 题 / 总计 50 题）。
* **实时自动保存**：每操作一题即刻云端同步，断网重新登录后 100% 恢复答题进度。
* **基础防作弊**：限制切屏次数，禁止右键复制，页面增加半透明实名水印。

#### 3.4.3 主观题作答（按卷配置）

* **模式A - 上传附件**：支持上传图片、文档、压缩包等附件作为答案。
* **模式B - 在线富文本**：支持在编辑器内直接输入答案，支持图文混排。

#### 3.4.4 提交流程与隐式算分

* **交卷拦截提示**：前置校验主观题附件/内容是否填写。点击"交卷"时，系统弹出阻断提示框，明确告知"未答数量 / 已答数量"，学生可选"返回试卷"继续答题，或"确认交卷"。
* **客观题即时计算（API静默处理）**：交卷成功后，后台 API 需立即对客观题进行自动判卷并得出得分，但**该分数对学生绝对不可见**。待评卷老师完成主观题打分后，系统自动将其与客观题得分相加，得出最终总成绩。

#### 3.4.4 成绩发布与申诉闭环

* **成绩门禁**：在到达管理员设定的"公布成绩时间"之前，成绩查询入口封闭，页面仅展示"预计公布成绩时间：XXXX-XX-XX XX:XX"。
* **复查时效提示**：成绩公布页面同时展示"复查申请截止时间：成绩公布后48小时内"。
* **成绩查询**：到达公布成绩时间后，学生方可查阅总分、客观题成绩、主观题得分及裁判评分表扫描件。
* **复查申请**：对成绩有异议可在公布后48小时内点击"申请复查"提交理由（每场限1次，生命周期内不可再次申请）。
* **复查处理后可见内容**：管理员及评卷老师复查完毕后，学生可查看复查结论（维持原判/已更正）、最新成绩明细及评卷老师给出的复核理由与评语。

### 3.5 评卷老师端 (Reviewer)

服务于赛事评卷，确保主观题评分的公平性与复核闭环。

#### 3.5.1 首页工作看板

* **评卷统计**：展示"待评阅试卷数"、"已评阅数"。
* **截止时间倒计时**：距离阅卷截止时间的倒计时进度条。
* **待处理复查申请**：设立专属的"待处理复查申请"高亮提醒模块。

#### 3.5.2 赛后评卷与实时统分

* **任务分配**：考试全部结束后，系统自动按"随机+工作量均衡"分配评卷任务，支持管理员人工调整。
* **在线独立打分**：在工作台查阅考生的主观题作答（附件下载预览或富文本查看），在线录入分数。
* **智能统分引擎**：当考生的主观题被所有分配的老师打分完毕后，系统立即按**平均分**规则得出主观题最终成绩并自动与此前的客观题得分合成总分。
* **线下凭证留存**：支持上传纸质评分表电子扫描件作为补充归档。

#### 3.5.3 成绩复核与重判工作台（闭环处理）

* **回避原则**：复查老师必须与原评卷老师不同，系统随机分配时自动排除原评卷老师。
* **复查工单处理**：进入复查专属页面，查看学生提交的"复查理由"及原卷附件。
* **重判决策与强制留痕**：判断"维持原判"或"同意重新打分"，系统强制要求填写"复查意见/理由"，直接同步至学生端。

## 4. 各角色业务流程详解

### 4.1 管理员业务流程

#### 4.1.1 赛前准备流程

```
1. 导入学生/教师名单（Excel模板）
   ↓
2. 批量生成账号（均关联学段：小学/初中）
   ├── 训练账号（学生）
   ├── 考试账号（学生，身份证+统一密码）
   └── 教师账号（指导老师/评卷老师）
   ↓
3. 生成四类激活码（支持快捷周期配置或自定义起止日期，支持重新激活）
   └── 教师激活码仅解锁对应学段题库和资源中心，与角色权限无关
   ↓
4. 配置教师角色权限（管理员为教师账号分配指导老师/评卷老师/双重角色）
   ↓
5. 配置教师-学生关联关系
   ├── 【名单补全】手工为训练账号指定指导老师
   ├── 【批量关联】通过Excel批量导入教师-学生关联（覆盖原关联）
   └── 【关联管理】查看/修改已有关联关系
   └── 约束：仅训练账号关联指导老师，考试账号不关联
   ↓
6. 搭建题库（按学段区分）
   ↓
6. 组卷管理
   ├── 【考试卷】→ 配置学段，用于正式考试（1卷1场次）
   └── 主观题作答方式配置（按卷二选一：上传附件/富文本）
   ↓
7. 创建考试场次
   ├── 选择学段（小学/初中）
   ├── 配置时间轴：起始时间 + 时间长度（快捷/自定义）→ 自动算结束时间
   ├── 配置白名单（该学段下的考试账号）
   └── 绑定唯一考试卷（强制同学段）
   ↓
8. 配置成绩公布策略
   ├── 含主观题场次 → 评卷完成后设置公布时间（精确到hh:mm，到期自动公布）
   └── 纯客观题场次 → 考前配置（交卷后立即公布/指定统一时间）
   ↓
9. 【固定规则】评卷规则：取平均分
   ↓
10. 发布考试/开放激活
```

#### 4.1.2 赛中监控流程

```
1. 考场监控大盘（实时在线人数、交卷人数、异常掉线）
   ↓
2. 应急处理（全局延时/单人补时）
   ↓
3. 强制收卷（必要时）
```

#### 4.1.3 赛后处理流程（含主观题）

```
1. 考试结束（全场次时间到或强制结束）
   ↓
2. 【统一分配】评卷任务（考试全部结束后，随机+工作量均衡）
   └── 支持管理员人工调整/转移任务
   ↓
3. 监控评卷进度
   ↓
4. 全部评卷完成 → 设置成绩公布时间（精确到hh:mm，到期自动公布）
   ↓
5. 处理复查申请（公布后48小时内，排除原评卷老师后随机分配复查老师）
   ↓
6. 复查完成 → 同步结论至学生端（不可再次申请）
   ↓
7. 多维成绩导出（完整版/脱敏版）
   ↓
8. 【可选】考试卷转历年真题卷
   ├── 确认开放
   ├── 学段继承原考试卷（无需额外配置）
   └── 可见范围：同学段所有训练账号
```

---

### 4.2 指导老师业务流程

```
1. 激活教师账号（关联学段）
   ↓
2. 管理员配置：指导老师 ↔ 学生关联关系（仅绑定同学段训练账号）
   ↓
3. 登录教师端
   ↓
4. 学情分析看板（查看所带学生数据）
   ↓
5. 组卷管理 → 组【练习卷】
   ├── 配置对应学段（与自己同学段）
```

```
   └── 若考试卷学段 ≠ 学生账号学段，禁止进入

   ├── 答题矩阵导航（未答/已答/当前题状态）

   ├── 校验主观题附件/内容
   ├── 提示未答数量/已答数量

```

## 5. 关键业务规则总表

| 模块 | 规则 | 说明 |
|-----|------|------|
| **账号学段** | 训练账号、考试账号、教师账号均关联学段（小学/初中） | — |
| **教师角色** | 指导老师、评卷老师为独立角色，同一账号可同时拥有 | 激活码仅解锁资源，与角色权限无关 |
| **组卷分工** | 管理员组考试卷；指导老师组练习卷 | — |
| **考试卷绑定** | 1个考试卷只能绑定1个场次（一对一），不允许多场次共用 | — |
| **主观题作答** | 按卷配置二选一：上传附件 / 在线富文本 | 整份试卷统一方式 |
| **激活码周期** | 快捷配置（3个月/半年/1年）或自定义起止日期；支持重新激活 | 重新激活默认上次周期 |
| **师生关联** | 训练账号可关联指导老师，支持手工/批量关联 | 学生可更换老师，批量导入时覆盖原关联 |
| **练习卷可见** | 指导老师组的卷 → 仅自己所带的训练账号可见 | 同学段其他学生不可见 |
| **历年真题卷** | 由考试卷转换而来，继承原学段，对同学段所有训练账号可见 | — |
| **考试账号关联** | 不关联指导老师 | 仅训练账号关联 |
| **评卷分配** | 考试全部结束后统一分配（随机+工作量均衡） | 支持管理员调整 |
| **评卷规则** | 固定取平均分 | — |
| **成绩公布** | 含主观题：设时间（hh:mm）到期自动公布；纯客观题：考前配置 | 无需手动开关 |
| **复查时效** | 成绩公布后48小时内可申请 | — |
| **复查次数** | 每场限1次，生命周期内不可重复 | — |
| **复查分配** | 排除原评卷老师后随机分配 | 回避原则 |
| **考试时间轴** | 起始时间 + 时间长度（快捷/自定义）→ 自动算结束时间，支持微调 | — |
| **学段匹配** | 考试账号、练习卷、考试卷、场次均需学段匹配 | 跨学段不可见/不可入 |

## 7. 关键状态流转规则总表

| 实体 | 关键流转规则 | 特殊说明 |
|-----|-------------|---------|
| **考试场次** | DRAFT → PENDING → OPEN → FINISHED/CLOSED → 评卷分配 | CLOSED和FINISHED都可评卷 |
| **试卷** | CREATED → ANSWERING → SUBMITTED → 等待评卷/自动算分 → 成绩公布 | — |
| **评卷任务** | PENDING → ASSIGNED → REVIEWING → COMPLETED → 触发统分 | 管理员可调整/转移 |
| **复查申请** | PENDING → ASSIGNED → REVIEWING → UPHOLD/MODIFIED/REJECTED → CLOSED | 48小时时效，回避原则 |
| **成绩** | CALCULATED → PENDING → SCHEDULED → PUBLISHED → FINALIZED | 到期自动公布 |
| **激活码** | NOT_EFFECTIVE → ACTIVE → USED/EXPIRED → 管理员选择重新激活 | 移除FROZEN，重新激活可配未来时间或立即生效 |
| **账号** | LOCKED → 管理员解锁/重置密码 → ENABLED | 重置密码后可复制 |
| **练习卷** | EXPIRED → 指导老师重新激活 → PUBLISHED | 可重新发布 |
| **题目** | DEPRECATED → 管理员重新激活 → PUBLISHED | 或创建新版 |

## 8. 关键性能指标与非功能性需求 (NFR)

* **高并发承载性能（核心重点）**：考场开考瞬间需支持 1000 - 3000 QPS；答卷提交瞬间 API 即时算分的逻辑需做异步削峰处理（防堵塞）；答题期自动保存需具备防抖与高并发写入能力。
* **数据高可用与安全性**：主观题大附件采用分片上传与断点续传；训练与考试数据严格隔离；敏感数据加密存储。
* **操作溯源机制**：详细记录所有核心操作日志（含管理员修改场次时间轴、评卷老师打分/重判修改痕迹、学生上传/交卷操作等）。

## 9. 系统架构设计（混合架构）

### 9.1 架构选型：混合架构（单体 + 服务化）

#### 9.1.1 架构定位

本系统采用**混合架构**（Hybrid Architecture），即：
- **高并发核心链路**：拆分为独立部署的服务（可独立扩容）
- **常规业务模块**：保持单体应用（简化运维）

**为什么不采用纯微服务？**
- 并发量有限（2000人并发属于中低负载）
- 团队规模小（微服务需要专门运维团队）
- 业务边界清晰（仅"考试期间"需要高并发）
- 避免过度设计（减少分布式事务复杂度）

- 成绩服务 → MQ → 核心单体：成绩计算完成通知

```
   ├── 前端触发 online 事件

   ├── 服务端返回该考生最后保存时间
   └── 客户端对比时间戳，合并冲突（取最新）

3. 同步完成后
   └── 更新 LocalStorage _lastSync 标记
   └── 提示用户"答题进度已同步"
```

#### 9.4.2 交卷处理流程

```java
@PostMapping("/submit")
public Result<SubmitVO> submit(Long paperId) {
    // 1. 快速幂等校验（Redis原子操作）
    String lockKey = "exam:submit:" + paperId;
    Boolean locked = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 5, TimeUnit.MINUTES);
    
    if (!locked) {
        // 已提交或处理中
        String status = redisTemplate.opsForValue().get(lockKey);
        return Result.ok(new SubmitVO("处理中", "PENDING"));
    }
    
    // 2. 快速标记已提交（防重复提交）
    redisTemplate.opsForValue().set("exam:status:" + paperId, "SUBMITTED");
    
    // 3. 发送MQ，立即返回（不等待处理结果）
    rabbitTemplate.send("exam.submit.queue", paperId);
    
    return Result.ok(new SubmitVO("已提交", "ACCEPTED"));
}
```

```java
@Component
public class SubmitConsumer {
    
    @RabbitListener(
        queues = "exam.submit.queue",
        containerFactory = "batchListenerFactory"
    )
    public void onMessage(List<Message<Long>> messages) {
        // 1. 去重（防重复提交）
        List<Long> paperIds = messages.stream()
            .map(Message::getPayload)
            .distinct()
            .collect(Collectors.toList());
        
        // 2. 批量从Redis读取答题卡
        Map<Long, Map<String, String>> allAnswers = 
            batchReadFromRedis(paperIds);
        
        // 3. 批量计算客观题得分
        Map<Long, BigDecimal> scores = 
            scoreCalculator.batchCalculate(allAnswers);
        
        // 4. 批量插入数据库（单条SQL）
        answerRepository.batchInsertAnswers(allAnswers);
        answerRepository.batchInsertScores(scores);
        
        // 5. 批量清理Redis
        batchCleanRedis(paperIds);
        
        log.info("批量处理 {} 份交卷", paperIds.size());
    }
}
```

### 9.5 降级预案

| 故障场景 | 降级策略 | 用户体验 |
|---------|---------|---------|
| Redis故障 | 仅LocalStorage保存，标记"待同步" | 正常答题，恢复后自动同步 |
| MQ堆积(>5000) | 直接同步处理（牺牲性能保可用） | 交卷稍慢，但成功 |
| 数据库连接满 | 交卷入队延迟处理，返回"处理中" | 稍后可在成绩页查看状态 |
| 网络中断 | LocalStorage持续保存，恢复后同步 | 无感知 |
| 浏览器崩溃 | 重新登录后从Redis恢复 | 答题进度100%恢复 |
